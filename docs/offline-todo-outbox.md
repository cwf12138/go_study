# D-10 第三批 · 本机收集待办

交付日期：2026-11-04。解决「电脑不在线时，先把一件事记下来」：新增待办保存在当前设备，恢复连接后手动提交到原账号的收集箱。不增加一级页面，不把只读快照改成可编辑数据，也不自动同步。

## 如何使用

1. 在线登录新版服务，在「待办清单」点击 **＋ 本机收集**。首次打开会记录已核验的账号与电脑地址，不需要开启只读资料保留。
2. 点击「新建本机待办」，填写标题、备注、优先级。输入后自动保留，也可点击「保存到本机」。只有 IndexedDB 事务成功后才显示「本机已保存」。
3. 断网时继续使用同一入口。网页需事先准备并收藏同一地址的 `/offline/#capture`；安卓连接页可打开「离线资料与本机收集」，无需加载完整应用。
4. 联网后点击「核验并提交到收集箱」。先向原服务核验当前账号，再固定这条记录的提交标识与内容；成功后本机保留原文和回执。
5. 若显示「需核对结果」，先点击「核对服务端回执」。核对不会再次创建任务；需要重试时，只能手动沿用原标识和原内容。

网页离线启动仍受浏览器安全上下文限制：HTTPS / localhost 可准备公开资源缓存，普通局域网 HTTP 不保证断网冷启动。安卓资源随包内置；本次只完成资源同步与模拟桥验证，尚无 APK / 真机验收。

## 状态与操作

| 状态 | 可以做什么 | 提交含义 |
| --- | --- | --- |
| 本机草稿 | 编辑、保存、导出、另存、删除本机记录 | 没有发送到服务，联网也不会自动发送。 |
| 提交内容已固定 / 需核对结果 | 核对回执、手动原样重试、导出 | 原标识与内容不可编辑，防止同一次操作变成不同命令。 |
| 标识冲突 | 保留、导出、核对；明确需要时另存新草稿 | 不自动换标识绕过冲突，不自动产生第二个任务。 |
| 已确认提交 | 核对、导出、清理本机确认记录 | 服务端任务可在正常待办页继续修改。这里保留首次提交内容。 |
| 已确认 · 任务已删除 | 核对、导出、清理 | 重放原提交不复活任务；本机已知删除后，即使后来缺少回执也禁止恢复这次提交。 |
| 回执待核对 | 稍后核对，确认收集箱后显式按原标识恢复 | 适用于服务恢复旧备份等情况；没有新 ID，也不自动补发。 |

删除本机记录不撤销服务端任务。「清理已确认」只清理无回执疑问的确认记录，保留草稿、待核对与冲突记录。另存新草稿会生成新的提交身份，应先核对原记录是否已经提交。

## 保存、容量与账号边界

- 本机正文使用 IndexedDB 数据库 `daynest.todo-outbox.v1`。每个账号 / 服务最多 40 条、1 MiB，包括确认历史；超限拒绝新保存，不淘汰未发送内容。浏览器存储仍可能被用户清除或系统回收，不是备份。
- 自动保存采用版本条件与读写事务。两窗口改同一草稿时保留冲突窗口里的文字，可明确另存；不会静默覆盖另一窗口。提交前在事务中固定内容并取得短期占用，防止两窗口同时改命令。
- 正式提交标题 1–200 字、备注最多 6000 字，按 Unicode 字符计算；首尾空白规范化。草稿允许更长的暂存文字，提交前要求缩短。只有标题、备注、优先级；暂不支持离线修改 / 完成 / 删除已有待办、日期、步骤、分类或周期事项。
- 本机账号索引按已在线核验的账号 / 服务隔离，只保存令牌摘要，不复制原始令牌到本机待办。提交时仍必须在线 `GET /api/v1/me`，不把离线索引视为服务端授权。
- 退出或已知登录过期时锁定入口、清空旧界面，但保留未发送内容；在线重新登录原账号并打开本机收集后恢复。切账号 / 电脑不将旧记录发送给新账号。清除只读资料不会清除本机收集。
- 内容未加密，不适合作为共享设备的保密库。可显式导出当前文字为 Markdown、删除本机记录。设备端草稿与确认副本不包含在服务端备份或个人 JSON 中。

## 服务端提交契约

- `POST /api/v1/todo-imports`，严格字段：`schema_version: 1`、`request_id`、`title`、`notes`、`priority`。首次 201，相同账号 / 标识 / 原内容重试 200；同标识不同原内容 409。
- `GET /api/v1/todo-imports/{request_id}`，只查询当前账号。结果包含永久回执与当前目标任务；目标已删除时 `todo: null`，回执仍存在。
- Memory 在同一锁中创建必要的收集箱、待办和回执；不会出现任务创建成功却没有回执的中间状态。同一 ID 在不同账号下独立，目标被之后的在线编辑修改时，重试也不覆盖这些修改。
- 指纹使用 SHA-256：依次拼接协议名 `daynest.todo-import.v1`、规范化标题、备注、优先级，各段为 UTF-8 字节数十进制 + 冒号 + 原文。Go / JS 共享固定测试向量，避免 JSON 转义差异。指纹用于核对提交内容，不替代认证。
- 回执纳入 `todo_imports` 快照集合、个人导出、数据统计和完整备份引用校验。保留回执时，重试不会重建已经删除的目标；跨账号引用拒绝，历史缺失目标作为警告。
- **沿用每 15 秒周期 JSON 快照。HTTP 成功及回执确认不等于立即写盘。** 异常退出或恢复旧备份可能缺少最近的任务 / 回执；本机确认记录不会自动清理，需主动核对，再选择是否使用原标识恢复。只有原回执保留时才承诺服务端去重，不声称跨备份回滚的永久恰好一次。
- 网络恢复、刷新、重开、重新登录均不自动重发写入。旧服务不支持接口时，保留原命令并提示重启新版 Go；不降级成普通 `/todos` 创建。安卓冷启动桥只允许核验账号和读写本次回执接口，并检查所选电脑、令牌与会话代次。
