## 使用上的变化

- 取消等待、超时、断线、返回内容异常与版本冲突分开处理。数据中心取消后保留已有状态，不显示为检查成功；关闭弹窗或切账号后的迟到结果不更新页面。
- 收到当前会话的 401 时，显示「登录已过期，先留住正在写的内容」。编辑区和本机草稿仍在，当前令牌不自动清除；可以先导出本机文字，再点击「重新登录」。
- 「重新登录」复用已有退出保护。有未提交内容时会确认；取消确认不会离开编辑区。确认后才退出，原账号本机草稿按既有规则保留。
- 已确认过期后，这两个模块与主应用的普通受保护请求会停止重复发送，直到会话变化。主应用认证接口仍可用于重新登录。其他尚未迁移的独立模块不保证采用同样的请求抑制规则。
- 备忘录新建期间禁用新建按钮和模板，同时拦截重复快捷键。只等待同一次操作，不再因连续点击发送多个新建请求。
- 新建遇到断网、超时或异常成功响应，无法确认结果时，显示核对区并阻止再次新建。先刷新列表，检查是否已有新记录，再明确点击「已核对，允许再次新建」。此按钮不会自动创建新记录。
- 保存遇到 401、冲突或结果不确定时保留文字，暂停该编辑区的自动提交，改为先核对再手动保存。

**这不是新建幂等协议。** 核对区属于当前页面状态，刷新后不持久化该操作门槛；新建超时或刷新前后仍应先检查列表。请求发出后取消，不证明服务端已经撤销操作，也不会自动重发写入。另存副本、其他模块和旧客户端仍需各自处理未知结果。

## 共用传输契约

`http-client.js` 提供 `DaynestHTTP.json(path, options)`。只接收 `/api/v1/` 相对地址，拒绝外部 URL、路径跳转与片段；使用当前上下文的 Bearer 令牌，禁止请求参数覆盖为其他令牌，并禁止跟随 HTTP 重定向。

```javascript
const overview = await DaynestHTTP.json('/api/v1/data-center', {
  signal: controller.signal,
  timeoutMs: 20000,
});
```

支持 JSON 字符串或可序列化对象作为 body，成功返回 `data`，`envelope: true` 时保留顶层元数据。204 返回 null。成功响应必须是合法 JSON 且包含 `data`；HTML 错误页、缺字段、JSON 后多余字符不会被当作成功。

默认超时 25 秒，数据中心概览 20 秒、检查 120 秒；调用方取消与超时合并，覆盖发送及读取响应。即使底层等待没有及时响应 AbortSignal，当前界面也会结束等待，释放本层计时器与监听。安卓桥自身的连接 / 读取期限可能更早结束请求，不能把客户端的 120 秒视为原生网络层保证。

默认 JSON 响应读取上限 32 MiB，可由调用方在 64 MiB 以内调整；正常浏览器响应边读边限制。原生桥可能先接收响应后再交给此层，因此该上限不等于原生网络层的总内存限制。文件导出继续使用原有单独的 64 MiB 通道。

`DaynestRequestError` 提供：

- `kind`：http、auth、network、timeout、cancelled、account_changed、invalid_response、too_large、invalid_request 或 context。
- `status` / `code`：可用时保留 HTTP 状态与业务错误码。
- `uncertain`：已发出的写入遇到断线、取消、超时、服务错误或异常成功响应，结果可能无法确认；不是重试许可或提交证明。

客户端不自动重试读写请求，也不自动合并任意两个写入。重复点击保护由模块按业务处理，不能把不同内容误当作同一次请求。备忘录既有保存串行与版本条件保持不变。

## 账号、服务器与会话隔离

上下文包含当前令牌、服务地址、已验证账号及本页会话代次。请求发出前、收到响应后及解析完成后均核对；旧上下文可以主动取消。退出并快速登录同一账号、甚至服务器发回同一令牌时，也不接收上一次会话的迟到结果。

主应用的 `DaynestAccount.current()` 增加本页 `sessionID`。它不写入本机草稿键，登录更新不会把同账号历史草稿分割成新的空间，也不产生新的服务器权限。真正鉴权仍由后端执行。

只有当前上下文的 401 能标记会话过期；旧账号 / 旧服务器 / 旧会话返回的 401 不清除新账号，也不显示过期通知。401 不依赖响应体能否解析，以免 HTML 登录错误页掩盖真实状态。响应原文、令牌、请求头和正文不写入诊断报告。

当前只是两模块试点，未把全部独立请求模块统一，也不代表离线同步、跨端事务或立即写盘已经完成。
