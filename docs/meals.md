# 今天吃什么：给纠结一个答案

这个页面是吃饭决策工具，不再是厨房管理。你不需要先想好菜名，不需要自己做，也不必创建菜谱。

## 三步使用

1. 描述现在的情况，比如“刚下班很饿，想点外卖，预算40元，不吃辣，也不吃牛肉”。也可以不填文字，直接推荐。
2. 点“帮我决定这顿吃什么”：给出一个主推荐和最多两个备选，展示食物、推荐理由、点单组合与粗略参考预算。
3. 选“就吃这个”结束纠结；复制点单关键词，到你常用的外卖、地图或门店页面确认实际菜单与价格。页面不会自动下单。

可以“换一批”，尽量避开当前页面最近推荐；“这次不想吃”在本轮排除该食物，改动条件开启新一轮时清除。本轮候选有限时会说明重复或没有结果，不自动取消忌口。

## 条件与当前情况

- 默认餐次按中国标准时间选早餐、午餐、晚餐或加餐，可手动修改。
- 每人预算、外卖/到店/买现成、口味直接选择。食量、素食和排除内容在“还有一点偏好”内，不要求填写。
- 默认本地模式，38个原创点单组合方向，不依赖 AI 或网络。覆盖饭类、面食、饺子、便当、便利店食品、早餐和加餐；价格区间只是粗略参考，不是网站实时报价。
- 本地自由文本仅识别部分明确关键词：外卖/到店/便利店、不吃辣/清淡、很饿/不太饿、吃素、预算数字，以及“不吃/不要/忌口”后的部分内容。识别到的条件会显示在表单下方。不具备完整自然语言理解，也不自动读取位置、天气或其他模块；复杂描述请使用 AI。
- 结构化预算和偏好会检查每个候选；范围内没有合适内容就提示调整条件，不伪造“精确满足”的答案。
- 复制不可用时提供可选中的文本框，方便手动复制。退出或切换账号清除输入与结果；不持久化个人口味、历史或消费记录。

## 可选 AI

右上角“AI 连接设置”保留 ChatGPT Plus 官方授权与可用模型选择；连接后在表单选择“AI 按情况推荐”。只发送这次的需求与条件，以及最近推荐的标题，用于减少重复。不给出菜谱、食材用量或烹饪步骤，不读取其他模块。

AI失败会明确报告；可手动点击“先用本地推荐给我答案”，不会自动重试、切换计费或偷偷把本地结果说成 AI。支持取消在途请求，迟到的旧请求或旧账号结果不会覆盖新状态。已执行的推理可能仍消耗额度。

详见 [AI 连接、网络与隐私说明](ai-kitchen.md)。

## 真实边界

尚未接入实时餐厅/外卖数据，没有实际定位查询、下单、支付或外卖应用深链。不会保证附近有售、配送时间、份量、价格或优惠。预算可能不含配送费等，应以商家页面为准。

食物和调味品随门店变化。关键词筛选不是过敏安全保证，请向店家确认配料及交叉接触；不是医疗、减重或精确营养建议。

## 旧数据与接口

旧厨房前端不再启动，旧布局封存在惰性的 HTML template 中，不参与页面操作。原来的菜谱、菜单、购物记录、JSON快照和个人导出数据不删除、不迁移、不覆盖。旧 `/api/v1/meals`、保存和购物接口保留兼容性；新页面不会调用它们，也不偷偷创建旧菜谱。

`POST /api/v1/ai/meals/recommend` 的输入/输出已改为决策推荐：输入餐次、预算、就餐方式等，输出 `summary + choices`，不再接受旧 `people/minutes` 请求或返回 `recipes`。请更新已有自定义调用方，完整定义见 OpenAPI。

## 验证

重启 Go 服务并刷新后使用，无新增依赖。运行 `go test ./...`、`node tools/meal_ai_smoke.cjs`；旧 `meals_ui_smoke` 和 `meal_discovery_smoke` 仅验证保留的兼容逻辑，不表示旧厨房入口仍上线。

人工检查：电脑/手机宽度、夜间模式、键盘焦点、无候选、AI失败、本地切换、取消、复制失败和账号切换。自动测试采用模拟服务，不代表真实 Plus 授权或实时 AI 调用已成功。
