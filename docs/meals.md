# 今天吃什么

入口位于“今天”导航组。更新后重启 Go 服务并刷新页面；无需安装新依赖或修改环境变量。新增记录使用快照中的 `meals` 字段，旧快照没有此字段时视为空厨房，不改动其他数据。

## 从选菜到做饭

### 不用先想菜名：给我推荐一顿饭

顶部主按钮打开独立选餐器，空菜谱库也可推荐，无须先安装示例。

- 内置 34 道简明家常灵感，覆盖早餐、饭面、肉蛋豆腐菜、蔬菜、汤和米饭。参考 [豆果分类](https://m.douguo.com/fenlei) 与 [美食天下](https://m.meishichina.com/) 的餐次、食材和快手菜组织方式；做法为本站原创整理，不复制外站文章、图片，不实时抓取网站，也不代表平台热门排名。
- 选择早餐 / 午餐 / 晚餐、1–6 人、耗时和口味；正餐支持省事的一碗饭面、两菜一饭、三菜一汤一饭，早餐推荐早餐单品。香辣偏好要求正餐至少一道含辣；不吃辣则排除含辣的内置菜。
- 可选择不含肉鱼虾（仍可含蛋奶）、排除食材与常见成分。内置名称保守匹配，包括调味品中可能出现的大豆/麦类；不能保证无过敏原，请核查包装成分、交叉接触和自己的饮食限制。不是医疗或营养建议。
- “西红柿 / 番茄”“马铃薯 / 土豆”作为推荐筛选别名识别。家里已有食材提高候选排序权重，但不会因此绕过忌口。条件无解明确提示，不自动放宽限制。
- 人数会折算可识别的数字用量，个/根/片向上取整；“适量”等模糊用量不变。总耗时为各菜参考分钟之和，不假设并行烹饪，也不保证增加人数后仍能在同样时间完成。
- 推荐后可展开查看食材和步骤，锁定喜欢的菜，再换其余搭配。更改偏好会清除旧结果及锁定，避免使用不符合新条件的旧菜单。偏好和推荐结果暂存页面内存，退出或切换账号清空。
- 可收藏整餐菜谱、按日期与餐次安排整餐，或打开采购勾选窗口。写入前需要厨房同步完成。相同版本复用已有菜谱，个人修改或删除的版本不会被覆盖；必要时新建独立版本。重复排餐跳过已安排的同一道菜，保留完成状态。
- 收藏和排餐是逐条保存，不是整餐事务：中断时保留已成功记录。处理原有恢复栏的待确认请求后，再点击同一操作补齐；已保存或已安排的记录会跳过。采购仍使用既有原子批量接口。

### 我的菜谱库

1. 点击“添加示例菜谱”安装 8 道原创家常示例，也可手动记下拿手菜。示例不是抓取的外部菜谱；固定标识让重复点击不覆盖修改，也不会重新添加已删除示例。安装中断时，已成功添加的菜谱保留，重试待确认请求后可再次安装其余示例。
2. 食材每行填写 `名称 | 用量`，做法每行一个步骤。可记录分类、参考人数、耗时、备注和常吃标记。
3. 按菜名或食材搜索，叠加分类、耗时、常吃与食材备齐筛选。每页 9 道。随机选菜遵循当前筛选，多道候选时避免连续抽到上一道。
4. “家里有什么”按名称精确匹配，忽略大小写和多余空白；不会推断“西红柿”和“番茄”相同，也不会判断库存数量、新鲜度或过敏风险。已有食材仅保留在当前页面内存，刷新或切换账号清空。
5. 安排早、午、晚餐，一餐可选多道，但同一道菜不能重复安排。日期范围 2000–2100 年，今天和周起点按中国标准时间计算，周一开始。勾选已做并保留记录，可以撤销勾选。
6. 做饭详情有备料勾选、步骤勾选、大字模式与开始/暂停/继续/重置计时器。计时以截止时刻计算，关闭详情停止；步骤勾选仅暂存内存。网页不是系统闹钟，不保证关闭页面、休眠或后台时提醒，请勿依赖它看火。

## 与购物清单联动

- 从一道菜或当前周的未做菜单生成采购预览，一次最多 21 道；已有食材默认不勾选，可以手动调整。
- 整批请求先校验菜谱，再在同一写锁中添加。任何菜谱不存在或容量不足，整批失败，不会只添加一部分。
- 合并同名食材，已有待购买条目跳过，不覆盖数量、备注或常买标记。不会换算单位或自动相加；新条目数量为“按菜谱”，备注列出各菜参考用量，请结合人数自行调整。
- 成功后同步现有购物组件；若购物组件正在保存，会提示稍后刷新。“购物清单 ↗”可直接打开物品管家中的购物视图。
- 重复请求不会重复添加仍在待购买清单中的同名食材。如果之后把它标记买到，再次生成采购清单可以新增待购条目。

## 保存、安全与边界

- 每账号最多 3500 条菜谱与菜单（含已删除），与原有购物清单 2000 条上限分别计算。菜谱最多 40 项食材、30 个步骤；耗时 1–600 分钟，参考人数 1–20。
- 菜谱删除是软删除，不展示在菜谱库；为避免菜单引用失效，须先移除引用它的菜单记录。菜单保存当时的菜名，之后改名不改历史标题；做法与采购使用当前菜谱内容。
- 编辑未保存时关闭需要确认；未知保存结果和版本冲突保留完整请求，可关闭弹窗后导出草稿、原样重试或重新核对。重新核对会放弃本地请求，请先导出。账号切换立即清空内存并中止网络请求。
- 记录接入既有周期快照和正常退出保存机制，不是每次点击立即落盘。个人 JSON 导出包含 `meals` 和计数；草稿及导出未加密。
- 不提供远程图片抓取、营养诊断或自动库存扣减。示例做法、人数与时间仅供参考，请注意食品安全和过敏原。

## 接口与验证

- `GET /api/v1/meals`：当前账号全部菜谱和菜单，含软删除记录。
- `PUT /api/v1/meals/{id}`：完整保存，`kind` 为 `recipe` 或 `plan`，传入期望 `revision`（新建为 0）。相同请求幂等重试，旧版本不同内容返回 409。
- `POST /api/v1/meals/shopping`：`{"ids":["菜谱或菜单标识"],"have":["无需采购的食材名称"]}`，返回 `added` / `existing` 数量。需要登录。

验证：`go test ./...`、`node tools/meals_ui_smoke.cjs`、`node tools/meal_discovery_smoke.cjs`。前端测试是模拟 DOM 的交互回归，不代替真实浏览器截图验收。建议人工在桌面、手机宽度和夜间模式下检查：空菜谱库推荐、调整忌口、锁定换餐、整餐收藏/排餐/采购，以及原有安装示例、暂停计时和重启后菜单恢复。
