# 订阅管家

从左侧“记录 → 订阅管家”进入，也可通过快捷命令搜索名称。更新后重启 Go 服务并刷新页面；无需外部 API 或新增环境变量。

## 使用

1. 添加名称、每期人民币金额、扣费周期和下一次尚未支付的日期，可选分类、备注与状态。
2. 页面按进行中订阅计算月均和年度估算；未来 30 天（包含今天、不包含第 30 天后的日期）逐次列出预计扣费。
3. “今天及逾期”保留待确认项目。核实付款后点击“确认本期已付”，每次仅推进一个周期，不自动跳过逾期账期；未来日期不能提前确认。
4. 暂停、取消及回收站项目不参与估算。取消实际服务须自行到服务商操作；恢复进行中保留原日期，不自动跳过暂停期间的账期，可编辑下一扣费日。
5. 支持状态/分类/关键词筛选，按日期、名称或每期金额排序，每页 9 条；可编辑、移入回收站及恢复，导出当前筛选结果 CSV。

## 日期与金额

- 采用北京时间自然日。支持 2000–2100 年的日期，周/月/季/年四种周期。
- 每次扣费日期从原始日期推算：1 月 31 日 → 2 月月底 → 3 月 31 日；2 月 29 日年付 → 非闰年 2 月 28 日 → 闰年 2 月 29 日。不会因短月改变原扣费日。
- 编辑日期或周期时以新日期重设起点；保持原日期和周期时保留起点与已推进的周期数。
- 后端金额使用整数分，允许每期 0–1,000,000 元。月付年度估算乘 12、季付乘 4、年付按 1 次，周付以 365.2425/7 次估算；月均为年度估算除以 12 后按分取整。
- 估算假定当前价格持续，不考虑折扣、试用、税费和价格变化。未来预计扣费和待确认的逾期项目分别展示；逾期金额不计入未来窗口。
- 这里只记录最近一次确认支付日期，没有完整支付流水，不读取银行、不自动付款或取消、不自动记入生活账本；不提供后台通知。

## 保存

订阅按账号隔离，保存到现有 JSON 快照的 `subscriptions` 字段，也纳入个人 JSON 导出及数量统计。老快照没有此字段时正常加载为空，无需手工迁移。

保存携带 `revision`，不同窗口修改同一记录时检测冲突。网络失败或保存响应不完整时保留原请求，锁定继续修改，可原样重试；紧邻版本且内容相同的重试返回原结果，避免重复推进日期。版本冲突同样保留草稿，先导出再重新加载核对。明确校验失败时允许继续编辑表单。

退出或切换账号清理页面内容与未确认请求，旧请求不会写入新账号界面。未保存编辑关闭时确认；保存失败的草稿仅在当前页面内存中，请先重试或下载后再刷新。

沿用现有周期快照与停机保存机制：接口成功表示内存更新，异常断电仍可能损失尚未写盘的数据。此次开发未修改实际 `data/studyflow.json`。

## 接口与验证

- `GET /api/v1/subscriptions`：当前账号全部订阅，包含回收站。
- `PUT /api/v1/subscriptions/{id}`：完整保存，需要有效标识与期望版本。新记录 `revision=0`；缺失记录用非零版本保存返回 404，旧版本冲突返回 409。
- `go test ./...`：日期边界、金额校验、幂等保存、账号隔离、版本冲突、回收站、快照与个人导出，以及现有服务回归。
- `node tools/subscriptions_ui_smoke.cjs`：月底/闰年、周期预测、整数金额、分页、输入转义、支付推进、失败重试、草稿保留、编辑关闭与账号响应隔离。

前端已适配夜间主题、窄屏、键盘操作及减少动态效果。自动化测试使用模拟浏览器环境，真实浏览器视觉与触屏仍需实际验收。
