# D-08 第三批 · 智能日历的日程保存保护

交付日期：2026-11-05。延续待办的版本契约，完善日程的新建、整组编辑、删除与未知结果核对，保留原有年 / 月 / 周 / 日入口。

## 使用

重启 Go 并刷新网页，在智能日历中点击「新建日程」，或选择日期后点击「当日安排」里的日程。新编辑器支持手机滚动、固定标题 / 关闭按钮、底部保存区、深浅色及键盘操作。

- 标题 1–160 字，说明 6000 字、地点 240 字、分类 60 字，按 Unicode 字符计算。已有自定义分类和提醒值可以保留。
- 普通时间按北京时间输入；未改动的开始、结束和重复截止保留服务端原有秒 / 纳秒，不经过分钟输入框重新取整。
- 全天模式使用日期输入，结束日期**包含当天**，底层结束是次日 00:00。全天和跨夜日程在每个覆盖日期展示；周 / 日视图增加全天区，跨午夜的时间块按日裁切。
- 从重复实例进入时读取原始系列，明确提示修改 / 删除作用于整组。不会把点击的后续实例日期误写成首次开始时间；本批没有单次实例例外编辑。
- 保存期间继续输入会保留，响应只确认已发出的一版。新建提交固定后暂时只读，避免重试内容改变；确认后可继续正常编辑。

## 冲突与未知结果

编辑和删除使用读取时的完整版本。其他窗口 / 设备先修改过时，不覆盖新版本，保留当前文字；点击「读取最新版本」对照，再选择采用服务端内容，或明确保留当前字段继续编辑。

断网发生在核验阶段时尚未发送写入，可稍后手动保存；写入已经发出但响应丢失、超时或异常时，先核对结果，不自动重发。原日程已经删除时停用保存，当前文字仍可导出 Markdown，不重新创建成另一项。删除结果不明也先读取核对，不再重复执行删除。

登录过期保留编辑内容与导出；切换账号 / 服务清空旧 DOM、对照内容和自定义选项，迟到响应不恢复旧界面。初始化改为等待账号核验，避免直接刷新日历时因会话建立而忽略首个结果。

已有日程的未提交编辑暂存在当前页面，关闭 / 退出有未保存提示，需要长期保留时先导出。本批不是已有日程的离线编辑同步。

## 新建提交记录

新版新建使用稳定请求标识，在发送前同步保留完整原内容；保留失败时停止发送。服务端同一锁内保存日程和永久回执，同标识 / 同内容重试返回原回执与**当前**日程，不覆盖后续修改；更改原内容冲突，删除目标后回执仍在，重试不复活日程。

日历工具栏显示「待核对日程」或「新建记录」：

1. 选择本机记录，点击「读取最新版本」查询原回执。刷新 / 重新登录后仍可在原账号、原服务下找回。
2. 未找到回执时明确保留疑问；可以稍后再查，或手动按原标识、原内容重试，不产生新 ID。旧服务不支持新接口时保留原记录并提示重启，不降级成普通创建。
3. **收到成功确认后，原内容与确认标记继续保留在本机。** 可再次查询服务状态；如果服务恢复旧备份、回执变为缺失，疑问标记也会保留，需明确核对或按原标识恢复。
4. 曾确认目标已删除时，保留本机已删除标记；即使随后回执缺失或浏览器重开，也禁止恢复原创建。
5. 可单独清理，或从记录列表「清理已确认的本机记录」。批量只清理已确认且没有回执疑问的记录，不删除服务端日程，不淘汰待核对内容。

本机记录使用 `daynest.calendar-command.v1:` 命名空间，按已在线核验的账号 / 服务隔离，不复制令牌。每份命令最多 64 KiB，达到 20 条会拒绝新保留，需先导出 / 核对 / 清理；独立随机键避免两窗口互相覆盖原命令。容量检查不是跨窗口数据库事务，但不会通过覆盖另一条命令腾空间。

本机内容未加密，可能被浏览器清理，不是备份；退出和清理只读快照不会自动删除它们。设备端记录不在个人 JSON / 服务备份中；服务端回执纳入 `calendar_commands` 集合、导出、数据中心及完整备份。安卓电脑不可达的冷启动入口仍只覆盖既有离线阅读 / 待办收集；本批日程记录在在线核验原账号后打开。

## 数据契约

- `GET /api/v1/calendar/events/{event_id}`：原始系列、强 ETag、`meta.write_contract: calendar-if-match-v1`。
- `PATCH / DELETE /api/v1/calendar/events/{event_id}`：支持单个强 `If-Match`，旧版本返回 409，弱 / 多值 / 通配条件返回 400。旧客户端可省略条件，但服务端仍用刚读取的版本原子比较写入。
- `POST /api/v1/calendar/event-commands`：`schema_version: 1`、16–100 位安全字符请求 ID 和完整日程字段。首次 201，原样重试 200，改参 409。
- `GET /api/v1/calendar/event-commands/{request_id}`：只查询原账号回执，目标删除时 `event: null`。

新网页每次修改已有路由前都核验服务能力和点击版本，避免旧服务忽略未知请求头。普通查询与编辑使用共用客户端，保留取消、超时、非 JSON 401、账号 / 服务代次检查和规划快照作废。农历、黄历、历史来源保持原有入口。

指纹为长度前缀 UTF-8 SHA-256，依次包含 `daynest.calendar-create.v1`、规范化标题 / 说明 / 地点 / 分类 / 颜色、UTC RFC3339Nano 开始 / 结束、全天布尔、重复规则、UTC 截止或空串、提醒分钟。Go / JS 共享固定向量，指纹不替代认证。回执不复制服务端日程正文；备份对历史缺失目标作警告，拒绝跨账号引用。

**仍采用每 15 秒周期 JSON 快照，成功不等于立即落盘。** 有回执的状态下可以去重；恢复旧备份或异常退出丢失回执时，需要主动核对。本机确认副本降低疑虑，不能代替可靠数据库或备份。不承诺跨任意备份回滚的永久恰好一次。SQLite 原型没有接管这组能力。
