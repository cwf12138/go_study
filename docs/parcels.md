# 快递收件

从「今天」的「打开收件夹」进入，不新增侧栏页面。更新后请重启 Go 服务并刷新网页；只有刷新无法加载新后端接口。

## 出门取件的最短流程

1. 收到通知后点击「记个包裹」，填取件点和取件码，保存。两项可按实际情况选择填写；名称、取件点、取件码或单号中至少要有一项。
2. 出门前按取件点筛选待取包裹。取件码默认遮住，点击显示或复制；需要向工作人员展示时可主动开启大字模式。
3. 取走后点「已取件」。误操作可在「已取件」中撤销，重新回到待取清单。

名称不填时显示「快递包裹」。状态、快递公司、最晚取件日、单号和备注放在折叠的可选区域，不强迫填写。运输中包裹可手动标记到站；所有状态都以你确认为准，并非快递公司的实时状态。

## 短信辅助与隐私

- 只有你主动粘贴时才在本机识别“取件码 / 取货码 / 提货码”后的常见英数、横线和下划线格式；不读取手机短信，不调用 AI 或第三方接口。
- 成功提取后立即清空原短信，只把取件码填入表单，由你核对后保存。不可靠地识别时请手动填写，不会猜测普通验证码或短信中的其他数字。
- 默认遮码时，卡片 HTML 不含真实取件码。关闭弹窗、切换筛选或翻页会恢复遮码；编辑表单中仍会显示当前码，需注意周围环境。
- 复制只发生在点击后；浏览器拒绝剪贴板权限时提供手动复制框，关闭弹窗后清空。复制成功的内容仍可能留在系统剪贴板，请自行管理。
- 遮码不是加密。登录后列表接口会返回取件码；服务器 JSON 快照和个人数据导出也包含明文。请保护账号、数据目录及备份，不要保存身份证、支付密码或登录验证码。部署到非本机环境应使用 HTTPS。
- 退出/切换账号会清空此模块的内存、表单和待重试操作，并丢弃旧账号尚未返回的请求结果。

## 管理与保存

- 支持待取、运输中、已取、全部和回收站；搜索名称、快递公司、取件点、单号与备注，不通过搜索暴露遮住的码。每页 6 条，优先显示最早的自定取件日期。
- 最晚取件日由你自行填写，按北京时间自然日显示剩余/已过天数；不是驿站实际保管期限，不提供后台或系统通知。
- 移入回收站为软删除，可恢复；当前没有永久删除入口。每账号最多 2,000 条，含已取及回收站记录。
- 记录纳入现有 JSON 快照与个人 JSON 导出；不改动旧数据结构中的已有记录，后端继续沿用项目现有的定期快照与停机保存机制。保存成功表示服务内存已接受，不代表每次请求都立即写盘。
- 使用修订版本防止其他窗口无声覆盖。保存结果不确定时保留同一标识与请求，点击「原样重试保存」；冲突时先「重新读取并核对」。重新读取保留表单草稿，但不会自动合并冲突内容，请核对后再保存。
- 列表在登录/首次打开、手动同步或保存后更新；不是多设备实时推送。表单草稿与未确认的重试只存在当前页面，刷新前请自行保留。

## API 与验证

- `GET /api/v1/parcels`：当前账号全部记录，含回收站，响应禁止缓存。
- `PUT /api/v1/parcels/{id}`：完整保存记录；新建 `revision: 0`，修改传上次读取的版本，相同旧版本与相同内容的直接重试幂等。
- 接口需要现有 Bearer 登录令牌。未知字段、无效日期、控制字符和过长内容会被拒绝；版本冲突返回 409。

验证：`go test ./...`、`go vet ./...`、`node tools/parcels_smoke.cjs`。自动测试覆盖鉴权隔离、快照、导出、取件撤销、回收站恢复、遮码、复制回退、本机短信识别、原样重试、冲突及翻页；手机触屏和真实浏览器视觉效果需另外人工验收。
