# 数据安全与同步说明

## 启动保护

- 主快照损坏且存在有效备份：隔离损坏文件后，立即将有效备份重建为主快照，再恢复内存数据。恢复成功后即使尚未执行下一次定时保存就重启，也能直接加载主文件。
- 主快照损坏且没有有效备份：保留主文件和备份，报错并退出，不再以空数据继续运行。
- 主文件缺失但 `.bak` 存在：报错退出，需人工核验备份并恢复主文件。
- 主文件与备份都不存在：仍允许首次启动。
- HTTP 端口已被占用：读取快照前退出，不启动保存任务，也不执行最终快照写入。

故障时先复制保全原文件与备份，再进行恢复，不要直接删除文件来消除报错。本次升级没有修改实际用户快照。

以上不是跨进程文件锁。不同端口的多个进程仍不得共享同一数据文件。现有内存＋定时快照架构不保证突然断电前的所有操作都已落盘；公开部署需配置备份、恢复演练和持久化存储。

同一个 Memory 仓库实例的加载/保存操作使用独立快照锁串行执行；磁盘 I/O 不持有业务数据锁，避免两个快照保存操作相互交错。这不提供多个进程或多个仓库实例间的协调。

恢复过程中若主文件重建失败，会明确报错并停止恢复，错误包含隔离文件和备份位置；原损坏文件与备份保留供人工处理。

## 页面同步

公共状态栏展示核心模块加载情况，并提供手动刷新。概览、目标、心情、任务、待办、单词、规划、分析、周回顾、专注的请求可以分别成功或失败；失败模块保留上次内存数据，首次失败可能显示空内容，状态栏会列明失败模块。

阅读书房、备忘录等独立页面仍使用各自的加载和保存入口。“刷新数据”不是所有独立页面的统一保存按钮。

备忘录请求有 25 秒超时及响应期间的账号校验。接口不存在和单条资源已删除分别提示，不再把所有 404 都解释为旧后端；不完整的成功响应也会被识别为错误，而不是误标为保存成功。

常规请求超过 25 秒取消并提示；账号改变后忽略旧请求，避免旧会话的 401 响应退出新账号。核心模块每分钟自动刷新在后台标签页暂停，恢复联网时重新刷新。不支持离线保存。

## 检查与升级

### 编辑中的内容保护

- 备忘录连续搜索或快速切换笔记时，按最后一次请求决定展示内容，较早返回的结果不会覆盖新选择。
- 备忘录列表加载期间输入的新内容会保留；若切换笔记的请求期间继续输入，会提示先保存再切换。
- 规划设置有未保存修改时，不受核心模块自动刷新影响。可用“放弃修改”恢复当前已加载的服务器偏好，也可收起设置后继续编辑。
- 规划设置保存期间继续输入的内容作为新修改保留。规划草稿仅保留在页面内存中，刷新或关闭网页前会提示，不是离线草稿备份。

```powershell
go test ./...
node --check internal/httpapi/assets/app.js
node tools/app_sync_smoke.cjs
```

数据保护测试仅使用临时目录。前端测试使用模拟 DOM 与网络，不替代真实浏览器验收。升级后重启 Go 服务并刷新页面，无需修改快照格式。
