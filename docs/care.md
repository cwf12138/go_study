# 生活保养站

管理不需要每天打卡、但隔一段时间需要再照顾的小事。和习惯、待办、物品管理的区别是：保留周期、实际完成历史及下次日期，完成后自动推进下一期，而不是每天重建任务或登记库存。

更新后正常停止旧服务，重新运行 `go run ./cmd/api` 并刷新网页，从「今天 → 生活保养站」进入。无需 AI、网络服务、额外依赖或修改环境变量。本次没有改写实际数据文件。

## 使用方式

- 新增事项，设置分类、间隔、节奏、下次日期、预计时长、重要程度与备注。6 个生活示例只会预填表单，不自动创建记录；所有周期均为可调整示例，不是卫生、医疗或设备维护标准。设备相关检查和维护以产品说明与合适的专业指导为准。
- 「现在照顾」显示今天与已过计划日的活动事项；「即将到来」显示未来 7 天；「全部事项」包含暂停事项；「回收站」可恢复。支持名称/备注/分类搜索、分类筛选、日期/更新时间/名称排序，每页 8 项。
- 「完成了」打开确认弹窗，选择实际完成日期并写小记录；不晚于今天、不早于该事项上次完成日期。允许提前完成，弹窗会说明，并预览下次日期。预计分钟只用于安排，不会当作真实完成时长。
- 「推迟」只移动本期提醒，不算完成，不改变固定周期锚点；可选择晚于今天与原计划、且在未来 90 天内的日期。可在详情取消推迟、暂停/恢复提醒，或移入回收站。
- 点击标题查看完成历史，每页 10 条，最多保留最近 100 次；累计完成次数继续保留。最近一次完成可撤销，恢复原计划、推迟日期、上次完成日期及累计次数；即使触发历史截断，撤销也会恢复被挤出的记录。编辑、推迟、暂停、移除等后续操作会关闭撤销入口，不能连续撤销多次。
- CSV 导出当前筛选的事项，不是完整历史导出；完整数据含历史与回收站，已纳入个人 JSON 导出。文件包含个人备注，请自行保护。

## 两种节奏

**做完后重新计时**：从实际完成日期加上间隔。例：每月一次，2 月 28 日完成，下次为 3 月 28 日；晚完成会顺延。

**固定日历节奏**：一直以原计划日期为锚点。例：锚点 1 月 31 日，每月一次，短月为 2 月末，之后回到 3 月 31 日。错过多期时确认一次只增加一次实际完成，下一次跳到完成日期之后，不伪造漏掉期间的完成。提前完成则推进当前安排到下一期。

周期支持 1–365 天、1–52 周、1–24 个月，日期支持 2000–2100 年。编辑时改变周期、节奏或下次日期，会从新日期重新锚定，不删除完成历史；只改名称/备注不重设当前日程。下一次超出日期范围时拒绝完成，请先调整安排。

## 与智能日历联动

日历按原数据读取，不额外创建独立日程：活动事项显示**当前这一期**的到期日期（推迟后显示推迟日期），保留的完成记录显示实际完成日期。不会展开无限重复事件，也不提前猜测下一次的实际完成时间。暂停后隐藏待办日期但保留历史；移入回收站后隐藏全部相关日历记录，恢复后再出现。

支持月历、当日详情以及周/日视图的全天记录栏，来源筛选新增「生活保养」，可直接返回事项详情。同一天记录较多时，全天栏显示前三条和更多入口。完成历史超过 100 次后，只投影仍保留的历史。事项改名会同步更新日历中的显示名称。

同窗口使用事件刷新，同源其他标签页通过只含随机刷新标识的 storage 通知重新读取。不提供后台推送、系统闹钟、离线写入或跨设备主动同步；关闭网页不会提醒。其他设备需重新打开或刷新。

## 数据与可靠性

所有接口均需登录，按账号隔离；新 `care` 字段加入原有 JSON 快照及个人数据导出，没有此字段的旧快照仍可加载。每账号最多 500 项（含回收站），不永久删除。沿用周期快照与优雅退出保存；成功响应意味着已写内存，不保证当下立即落盘，强制结束进程可能丢失最近一个快照周期数据。

保存带版本号，操作带固定请求标识和指纹。网络断开、超时或响应异常时保留原请求并暂停新写入；可导出不含令牌的请求，再原样重试或核对。精确重试不重复完成或推进周期，冲突不静默覆盖。核对成功会关闭旧版本弹窗，请重新打开事项继续操作；先导出请求找回文字草稿。待确认请求和表单仅保留在页面内存，刷新或退出前请保存。

到期和近 7 天统计按中国标准时间及服务端时间偏移计算。完成统计基于保留的历史，不是完整审计账本。登录切换会清空页面记录、表单和待确认请求，迟到响应不会进入另一个账号。

## 开发

- `GET /api/v1/care-items`：当前账号全部事项（含回收站）、服务端 UTC 时间。
- `PUT /api/v1/care-items/{id}`：创建/编辑元数据，新建 revision=0；不能传入完成次数、历史或下次周期索引。
- `POST /api/v1/care-items/{id}/actions`：complete / undo / snooze / unsnooze / pause / resume / archive / restore，携带 command_id 和 revision。
- `GET /api/v1/calendar`：新增 `care_entries` 只读投影。

更多字段见 [OpenAPI](openapi.yaml)。后端测试覆盖月底/闰年、滚动/固定、错过多期、重试、撤销历史截断、权限、快照与个人导出；前端模拟测试覆盖真实 DOM 标识、创建、确认/撤销、推迟、暂停恢复、回收站、CSV、冲突、XSS 及账号隔离。
