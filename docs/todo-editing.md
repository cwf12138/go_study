# D-08 第二批 · 待办在线编辑与版本保护

交付日期：2026-11-05。为现有待办补齐详情编辑、并发保存保护与未知结果核对。入口保留在待办卡片，不增加一级页面。

## 使用方法

重启新版 Go 服务并刷新网页，在「待办清单」卡片点击 **编辑**。可调整标题、备注、分类、优先级、截止时间、我的一天日期、重复规则、标签和步骤；完成状态继续使用卡片上的完成按钮。

- 新步骤由服务分配 ID；修改既有步骤保留 ID 与创建信息。标题、备注与步骤按 Unicode 字符校验，分别为 200 / 6000 / 200 字，每项最多 30 个步骤。
- 未修改的截止时间保留原始秒与纳秒精度，避免浏览器分钟输入框在普通编辑时悄悄改动日期。
- 保存期间可以继续输入。响应只确认发出时的内容，之后的输入仍留在编辑区，需要再次保存；请求期间暂时禁止增删 / 重排步骤，以便正确接纳新步骤的服务端 ID。
- 手机使用固定标题 / 关闭按钮与可滚动编辑区，底部保留保存 / 导出操作；兼容深浅色、键盘焦点和系统减少动态效果。

## 多窗口与结果不明

| 情况 | 页面行为 | 后续操作 |
| --- | --- | --- |
| 其他窗口已修改、完成、勾选步骤或调整日期 | 保存拒绝覆盖新版本，当前文字保留 | 读取最新版本，对照后采用服务端内容，或明确保留当前可编辑字段再保存。 |
| 分类被删除 | 所属待办原子移回收集箱并更新版本 | 旧编辑会冲突；核对时刷新分类选项，重新选择有效分类或采用服务端版本。 |
| 断网、超时、响应丢失、异常成功响应 | 停止自动提交，保留编辑内容并要求核对 | 读取服务端结果；可先导出当前文字。联网后不会自动重发。 |
| 完成 / 日期 / 步骤 / 删除的结果不明 | 当前页面底部显示「待办操作待核对」提示 | 点击读取当前服务状态，再显式结束核对；不会重复发送原操作。 |
| 原任务已删除 | 保留当前文字与导出入口，停止保存 | 不自动把旧编辑重新创建成另一项。 |
| 登录已过期 | 保留编辑区与导出能力 | 先导出，再通过原有退出提示重新登录。换账号立即清空旧 DOM，迟到结果不恢复旧内容。 |

「保留我的文字，继续编辑」是明确选择：下次保存会替换编辑器中的可编辑字段，包括步骤集合；状态与来源回执继续采用服务端当前值。另一个窗口再次修改时仍会冲突，不提供跳过版本的强制覆盖。

2026-11-09 起，待办编辑支持本机草稿。标题、备注、日期、分类、标签和步骤在输入时保留，待办页「本机编辑草稿」提供预览、原任务对照、恢复、文字导出与清理。恢复先重新读取原任务，再进入版本对照，选择后手动提交。关闭保留设置后停止新增副本，已有副本仍可清理。成功提交后的副本继续保留，确认后由用户清理。草稿以明文存于当前设备，按账号和服务隔离，多窗口各自保留，容量与备忘录、心情及周复盘草稿共享 40 份 / 4 MiB 上限。空间失败会在编辑器提示导出。快捷完成、删除等操作的待核对提示仍保存在页面内存，新建离线待办见 [本机收集](offline-todo-outbox.md)。

## 后端契约

- `GET /api/v1/todos/{todo_id}` 返回当前账号所属任务、强 ETag 和 `meta.write_contract: todo-if-match-v1`。
- `PATCH /api/v1/todos/{todo_id}` 要求单个强 `If-Match`，内容是完整的可编辑字段替换。允许空日期 / 数组表示清空；不接受状态、账号、创建信息、来源回执或下一周期引用。
- 完成状态、我的一天、步骤、删除接口支持相同 `If-Match`。新网页均使用点击时的完整 `ID@updated_at`，保留纳秒，不经过 JavaScript Date 的毫秒转换。缺失 PATCH 条件或弱 / 多值 / 通配 ETag 返回 400；旧版本返回 409。
- 为兼容旧客户端，已有快速操作可省略条件，但服务端同样以刚读到的版本进行原子比较提交。新界面先通过单项读取确认服务支持版本契约，再发送这些旧有路由；旧服务即使忽略未知请求头，也不会被新界面降级写入。
- Memory 新增窄能力：同一锁内检查版本、目标分类并提交；分类移除 / 移动、删除亦为原子操作。固定或倒退时钟也递增纳秒，避免写入重用旧版本。没有扩充根仓储的大接口，也没有接入 SQLite 生产存储。
- **成功仍沿用 15 秒周期 JSON 快照，不等于立即落盘。** 异常退出和旧备份恢复的风险与现有服务相同；本轮没有引入事务数据库或全站离线同步。

待办列表 / 分类读取、详情、编辑、完成、我的一天、步骤与删除使用共用请求客户端。创建待办和分类管理的前端表单仍走现有主应用流程，不能把这批标记为全站请求迁移已完成。

## 周期事项

第一次完成周期待办时，在同一锁中更新原项并创建下一项；一处失败两处都不写入。原项持久保留 `next_todo_id`，重新打开后再次完成也不会生成第二个下一项；下一项后来被删除，或快照保存 / 重载后，仍不会通过重新完成原项把它复活。

新周期保留内容、分类与重复规则，重置步骤和完成状态；不会复制原始备忘录关联回执或本机收集回执。下一周期引用纳入快照 / 个人导出与备份核对；历史缺失目标作为警告，跨账号引用拒绝。

旧版本已经完成的周期事项没有这个引用，无法可靠追溯过去生成的下一项。本轮不猜测匹配或回填历史关系；新保证从使用新版逻辑的首次周期完成开始。
