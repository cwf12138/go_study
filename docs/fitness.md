# 运动日常

一个无需联网或 AI 的运动计划、跟练和回顾空间。更新后停止旧服务，重新运行 `go run ./cmd/api`，刷新网页，从侧栏「今天 → 运动日常」进入。静态资源嵌入 Go 程序，只刷新浏览器不能更新旧进程中的页面。

## 使用入口

### 锻炼打卡与智能日历联动

在「今日与计划」选择日期，点击「标记已锻炼」即可打卡；可以补记过去日期，不能提前打卡。手动打卡仅增加运动天数，不增加记录分钟、完成次数或组数。同一天完成跟练并保存总结，或补记运动后，也会自动显示「已锻炼」；提前结束、仍在训练或尚未保存总结不自动打卡，可根据实际情况手动确认。

智能日历从运动记录实时汇总，每天仅显示一条「运动 · 已锻炼」，不复制成独立日程。月视图显示记录，年视图显示日期标记，周/日视图显示全天运动栏；可按「锻炼记录」来源筛选，并从当日详情返回对应日期的运动页。运动页也可直达所选日期的智能日历。

撤销手动打卡不删除实际运动记录；还有完成或补记记录时，当天仍显示已锻炼。删除/恢复相关运动记录后，日历在下一次读取时自动反映当前数据。手动打卡和完成记录合并计算运动天数，不重复计数；提前结束的记录仍计入原来的记录分钟，但不自动增加已锻炼天数。

同一窗口切换页面会重新读取；同源浏览器其他标签页通过仅含随机刷新标识的 storage 通知触发读取，不把登录令牌或运动内容写进通知。不支持跨设备主动推送：其他设备需重新打开或刷新页面。同步失败时可使用页面同步/日历重试；保存结果不确定时仍使用原来的恢复栏核对。记录继续纳入现有快照与个人导出，无需迁移实际数据。

新增第四个标签 **饮食搭配**：24 个原创日常组合，支持日常均衡、训练日与减脂友好方向，餐次/场景/植物性/忌口筛选、换组、收藏、常用偏好和每日用餐安排。与原训练记录独立，纳入快照与个人导出；不是个人营养处方。详见 [饮食搭配说明](fitness-nutrition.md)。

- **今日与计划**：查看本周、选择日期、安排已保存的训练；支持跳过、重新安排待训练状态和移除。右侧回看当天记录，顶部显示本周记录分钟、完成次数、活动天数和确认完成组数。
- **训练库**：内置 5 套原创轻量示例、9 种动作提示；可预览后开始，或另存并调整。自己的训练支持动作增删排序、计次/计时、每组目标、组数、休息时长和提示。支持名称搜索、类型/器械筛选、删除及恢复。
- **运动记录**：跟练完成、提前结束、手动补记分开显示；按月份和状态筛选，每页 8 条，查看明细、移入回收站、恢复，以及导出当前筛选的 CSV。清空月份可查看全部月份。

无需先制定长期计划：选一套适合自己的示例，预览后开始即可。示例不会自动写进个人训练库；安排示例时先保存一份，后续会尝试复用内容相同的训练。

## 跟练交互与统计口径

1. 同一账号最多存在一场进行中或暂停的训练。跨标签页由服务端校验，不能重复启动。
2. 计次动作显示每组目标；计时动作显示倒计时。点击「完成本组」才记一次完成；倒计时归零只提示，不自动打勾，也不是传感器测量。允许按实际情况提前确认。
3. 有后续组时进入组间休息，可提前结束休息；休息结束仍由用户点击进入下一组。暂停冻结剩余时间和总时长，恢复继续计时。「跳过此动作」跳过该动作尚未完成的所有组，不记作完成。
4. 最后一组处理后暂停计时，填写体感（可不填）和后记，点击「保存训练总结」。全部跳过不能保存为完成，应选择「提前结束」。有部分跳过的训练可以结束为完成，但详情始终分别显示完成和跳过组数。
5. 提前结束保留实际确认的组数与记录时间，不计入完整完成次数。手动补记则计入完成次数；补记范围为 1–1440 分钟、今天及之前的有效日期。

**分钟是跟练的非暂停总时长，包含组间休息和等待确认的时间，不是净运动时长。** 每场上限 24 小时，不估算热量、步数或实际动作质量。浏览器关闭、设备休眠或离开页面不自动暂停；重新打开后依据服务端时间锚点恢复。需要中断请主动暂停。结束前的后记仅在页面内存中，刷新前请保存；完成/提前结束时才提交。

日期和周统计采用中国标准时间，周一开始；跨午夜训练归属启动日。周目标由自己设定（10–1200 分钟、1–14 次），只是个人记录目标，不等同于医学建议或中高强度运动达标。参考时长包含对计次动作的粗略估计，不保证真实完成耗时。

计划保存当时的训练内容快照。之后编辑或删除原训练不会更改已安排或已开始的内容；可以提前执行安排。完成关联训练时，计划在同一个仓储锁内更新为完成；提前结束不自动完成计划。训练进行中不能取消或改期关联计划。已完成安排不允许重新开启，可另建一项。移除计划为软删除，当前界面不提供计划回收站。

## 可靠性、隐私与边界

- 所有接口需要登录，每条记录归属账号；数据纳入原 JSON 快照及个人数据导出。新字段可兼容没有运动记录的旧快照，不会自动生成个人记录。未改写真实数据文件。
- 沿用项目周期快照和优雅退出保存机制，HTTP 成功代表已写内存，不代表本次已经落盘；强制结束进程可能丢失最近一个快照周期的数据。请正常停止服务，并定期备份。
- 保存使用版本号；训练操作还带不可变请求标识和内容指纹。响应丢失时保留原请求，原样重试不会重复记组。结果不确定时暂停新写入，恢复栏可下载不含登录令牌的请求，再重试或重新核对服务端。
- 恢复栏请求和未保存表单只在当前页面内存中；刷新前请先导出。跨窗口更新发生冲突时不静默覆盖，也不自动重放旧操作。相同请求只在尚未被后续操作推进时可直接重试；否则需核对当前记录。
- 每账号最多 5000 条记录（含软删除）。回收站并非永久删除，个人导出也包含这些条目。CSV 只导出当前筛选的非删除历史记录，并转义表格公式前缀。下载文件包含个人运动备注，请妥善保管。
- 无后台推送、离线写入、智能设备连接、人体姿态识别、音频教练或自动运动检测。不依赖此前的 ChatGPT 授权，也不调用外部 AI。

## 安全与资料来源

动作说明为简短的通用提示，不是医疗建议、康复方案或完整动作教学。只选适合自身能力、环境和身体状态的活动，循序渐进；使用稳固支撑，不忍痛坚持。有伤病、孕期或不确定是否适合运动时，先咨询合适的专业人员。图形人物仅为装饰，不是标准姿势示范。

示例参考 [NHS 的日常力量活动资料](https://www.nhs.uk/live-well/exercise/strength-exercises/)，活动选择原则参考 [CDC 的成人活动资料](https://www.cdc.gov/physical-activity-basics/adding-adults/index.html)，文字和组合为本项目自行编写，未转载图片或视频。

## API 与开发验证

接口说明见 [OpenAPI](openapi.yaml)：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/fitness` | 当前账号所有记录，包含软删除、进行中的训练和 `server_time` |
| `PUT /api/v1/fitness/{id}` | 保存 routine / plan / log / settings，携带 revision |
| `POST /api/v1/fitness/sessions/{id}/start` | 从训练、安排或直接传入动作开始 |
| `POST /api/v1/fitness/sessions/{id}/actions` | 暂停、恢复、确认组、休息切换、跳过、完成、停止等状态转换 |

`id` 和 `command_id` 为 8–80 位字母、数字、下划线或连字符。初次保存 revision=0；后续带读取到的版本。动作上限 16 项、每项 8 组、合计 64 组；服务端验证所有范围，客户端不能直接写 session 的计时或完成字段。

```powershell
go test ./...
go vet ./...
node tools/fitness_ui_smoke.cjs
node tools/daynest_ui_smoke.cjs
node tools/layout_smoke.cjs
```

服务测试覆盖时间推进、暂停、重复请求、并发启动、原计划快照、原子完成、权限隔离、导出和快照恢复；HTTP 测试覆盖鉴权、格式、范围、冲突和路由；前端模拟测试覆盖交互、丢失响应的原样重试及切换账号清理。
