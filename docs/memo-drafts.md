# 备忘录本机草稿与冲突恢复

交付日期：2026-11-02。对应路线图 D-06 的备忘录试点。第二批已将同一存储机制扩展至[心情与周复盘](record-drafts.md)，三类草稿共享总容量，旧备忘录格式兼容。正式服务仍使用内存仓储与周期 JSON 快照；没有迁移实际数据，也没有实现整站离线同步。

## 使用方式

重启 Go 服务并刷新网页，在「备忘录」顶部打开 **本机草稿**。

1. 修改标题、正文、标签、文件夹或颜色时，先同步保留一份本机草稿，再等待原有的 700ms 自动提交。
2. 刷新后不会自动提交历史草稿。打开草稿箱，查看本机文字与服务端正文、标题、标签、颜色和文件夹。
3. 原文未发生冲突时，选择「恢复到编辑区」。恢复后须点击「保存」或按 Ctrl/⌘ + S 才会提交；自动保存和导航不会代为确认。
4. 服务端也有修改时，阻止直接恢复到原记录，可以对照、导出文字，或「另存为新备忘录」。新记录放在默认文件夹，并加上「草稿恢复」标题后缀。
5. 若服务已接收文字、响应却丢失，本机草稿仍保留。重新核对发现内容一致时，显示「打开并核对」，无需再次覆盖原记录。空标题自动生成等无法明确确认一致的情况继续保留草稿，避免误清理。

原记录被移入回收站或永久删除时，不会自动恢复原记录；仍可导出草稿，或显式另存副本。另存若发生断网 / 超时而结果无法确认，请先刷新列表核对，避免重复创建；此版本不宣称新建接口具有幂等保证。

## 保存与保留边界

| 状态 | 含义 |
| --- | --- |
| 本机草稿已保留 | 当前编辑内容已写入本浏览器 / App 的 localStorage。 |
| 等待自动保存 / 正在保存 | 仍有待提交内容，保留原有退出保护。 |
| 已提交服务 | 服务已接收；不能推断已写入硬盘。服务仍按原有周期快照规则保存。 |
| 保存失败 / 需核对 | 保留编辑区和可用的本机草稿；不会自动取消版本条件覆盖服务端。 |

- 默认启用，可在草稿箱关闭「在此设备保留未提交草稿」。关闭不会自动删除已有草稿，重新开启会捕获当前未提交内容。
- 草稿按 **前端存储来源 + 服务地址 + 已验证账号 ID** 隔离。账号 ID 来自成功登录 / 会话恢复，令牌更新后仍能找回同账号草稿；不把访问令牌写入草稿内容或键名。地址 / 端口不同视作不同服务，不自动合并。
- 退出、切换账号、切换服务后立即清空编辑区与恢复预览；旧草稿保留在原命名空间。重新登录原账号与服务后可查看。账号或服务变化后的迟到响应不能清除新账号的内容。
- 每个编辑页面生成独立草稿 ID。两个标签页编辑同一备忘录时各自保留，不共享一个可互相覆盖的草稿键。每代使用独立键，先写入新一代，再清理本页旧一代；清理恢复来源时，也不会误删其他窗口刚写入的新一代。恢复来源只在明确成功后清理。
- 三类草稿共用容量检查，阈值为所有账号合计 40 份、按键和值 UTF-16 字节估算 4 MiB；多窗口同时写入可能短暂超出估算值，浏览器实际空间也可能更少。空间不足、权限限制或损坏会提示，不自动淘汰旧文字，也不误报保存成功。损坏内容留在本机，可显式清理。
- 支持删除单份或清理此账号 / 服务的全部草稿，不删除服务端备忘录、不清理其他账号草稿。正在编辑的文字仍在编辑区，继续编辑或切入后台可能重新生成草稿；需要停止保留时先关闭开关。
- 草稿是**明文**，同一系统用户可通过浏览器工具访问，不提供本地加密或系统锁。共用设备请导出后清理。浏览器清理数据、无痕会话结束、卸载 App 或系统清理均可能删除草稿，它不能替代备份。

登录后遇到网络中断，可以打开本机文字并导出；网页下载 Markdown，安卓沿用原生文件保存通道。尚不支持在完全断网时重新登录并加载整个应用，也不支持其他设备读取这些草稿。

## 接口与实现

`PATCH /api/v1/memos/{note_id}` 新增可选 `expected_updated_at`，内容为最近一次读取的精确 `updated_at` 字符串，不经 JavaScript 日期转换而损失纳秒精度。

Memory 仓储在同一互斥锁内比较版本与写入；过期版本、已移入回收站的记录返回 409，不存在的记录 / 文件夹仍按既有接口返回 404。业务时钟相同或回拨时，编辑、移入回收站和恢复的版本至少前进 1ns；删除文件夹也会使受影响备忘录的旧版本失效。新版前端的编辑、置顶与归档请求均带版本条件。旧 API 客户端省略该字段时仍使用原有无条件写入行为，因此不能将兼容旧客户端称为全面的多端冲突保障。

仓储通过一个窄的可选能力提供原子比较更新；不支持该能力的仓储必须拒绝条件写入，不允许回退成非原子的读取 / 写入。此改动没有把 SQLite 原型接入正式服务。冲突保护与普通 JSON 快照不等于跨模块事务。

`app.js` 提供只读的 `DaynestAccount.current()` 获取当前仍有效的已验证账号上下文；功能脚本既订阅登录事件，也可在晚加载时读取上下文，解决快速会话恢复早于脚本加载的时序问题。不会为了初始化备忘录而向整站重放登录事件。

## 验证

自动检查：

```powershell
go test ./...
go vet ./...
node tools/check.cjs
```

新增 `tools/memo_drafts_smoke.cjs`：存储隔离与配额、损坏保留、刷新恢复、手动确认、双窗口独立草稿、保存中继续输入、响应丢失、账号 / 服务切换、旧响应、关闭保留、脚本晚加载。Go 测试验证实际 HTTP 409、并发条件更新只有一个成功，以及固定时钟版本前进。

可重复的真实浏览器演练（需要本机 Playwright 与浏览器；不会安装依赖或修改实际数据）：

```powershell
go build -o .local/memo-drafts-api.exe ./cmd/api
# Playwright 已在 Node 模块路径中时不需要设置 PLAYWRIGHT_MODULE。
# 若使用已有浏览器，可通过 PLAYWRIGHT_EXECUTABLE 指定绝对路径。
node tools/memo_drafts_browser.cjs
```

脚本启动独立服务，使用临时账号和 `.local/memo-drafts-browser-*` 临时目录；报告与截图位于 `.local/checks/`。覆盖故意延迟脚本后的刷新恢复、手动提交、请求处理中继续编辑、两个真实页面的版本冲突与另存、390px / 桌面 / 深色布局，以及断网查看和模拟原生保存交接。临时目录保留便于检查，不读取项目实际 `data/`。

报告明确区分浏览器验证与真机验收：原生文件保存交接为模拟，未生成 APK，未测试安卓进程被系统终止后的真实恢复。安卓资源同步也不等于完成这项验收。

同样的恢复边界已扩展到[心情长文与周复盘](record-drafts.md)。后续继续补齐新建操作幂等与跨模块保存契约；安卓 SDK / APK / 真机门槛仍单独跟进。
