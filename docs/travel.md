# 旅行手账

把一趟旅行的安排、行李与花费放在一起，不必先构建项目看板。模块不依赖外部地图、旅游 API 或生成式服务，不发送你的目的地和行程给第三方。

## 开始使用

更新代码后停止旧服务，运行 `go run ./cmd/api` 并刷新页面。在左侧进入“旅行手账”，点击“计划一场旅行”，填写名称、目的地、日期和可选预算。

- **每日路线**：选择日期、添加行程、记录地点与备注。桌面可以拖动卡片到另一张卡片前，或拖到日期按钮换天；手机与键盘可用上下移按钮及编辑日期。也可按时间排序，无时间的行程排在最后。重叠时间会提醒，但不会阻止保存。
- **行李清单**：按分类添加数量，勾选已整理的物品；基础清单会跳过已有同名项。完成统计按“物品项”计算，不按件数。修改名称或数量可移除后重新添加。
- **旅行账单**：汇总每站的预计费用和手动记入的实际费用，显示分类构成、预算余额及差额。金额统一为人民币，使用整数分存储；不换汇，不读取支付记录，也不会重复写入生活账本。零预算表示未设置。
- **保存与回顾**：提交表单或点击勾选、排序后立即向服务器保存；表单编辑过程不会自动保存。旅行可以归档并恢复；归档时页面只读。导出行程会下载可离线阅读的 UTF-8 文本。移除行程会一并移除该站费用，确认保存后不能撤销。

日期和时间按目的地当地时间手动填写，不做时区转换；倒计时按本机日期计算。跨日行程需要拆分为两天。完成打卡不代表费用已支付。

## 保存安全

- 每次完整保存携带上次 `revision`。多窗口对同一旅行修改时，旧版本返回 409，不静默覆盖。
- 超时、网络故障或异常响应时保留本页待确认请求，可以原样重试；后端对紧邻版本的相同内容重试返回原结果，不重复创建或再次递增版本。
- 冲突时先“导出草稿”，再“放弃并重新载入”，根据草稿手动合并。草稿导出不含登录凭据；当前未提供自动合并或 JSON 导入。
- 待确认修改不保存在浏览器持久缓存里。离开页面会尝试触发浏览器未保存提醒，但浏览器可能忽略提醒；请勿在导出或保存前强制刷新/关闭页面。
- 切换账号会清空本页数据和草稿、取消旧请求，防止旧账号响应进入新账号页面。
- 保存沿用项目现有的内存仓储、周期 JSON 快照和正常停机保存机制。接口返回成功表示已写入内存，**不等于已同步落盘**；异常断电仍有快照间隔内的数据风险。正式生产部署应使用事务数据库和可靠备份。

每账号最多 50 趟旅行（含归档）；每趟连续 1–31 天、最多 200 个行程和 100 个行李项；单项金额最多 100 万元、物品数量 1–99。请求体仍受全站 1 MiB 上限约束，大量长备注可能提前达到此限制。暂不提供永久删除旅行、多人协作、附件、实时地图导航、订票或与智能日历自动同步。

快照新增可选 `travel_plans` 字段，旧快照直接兼容。个人完整 JSON 导出也包含该字段。备份和导出未加密，注意妥善保护；不要在备注记录证件号、支付密码等敏感信息。本次实现不读取或改写仓库内已有的真实数据文件。

## 验证与上线检查

```powershell
go test ./...
node tools/travel_ui_smoke.cjs
```

新增测试覆盖账号隔离、幂等保存、并发冲突、日期/金额/数量校验、快照恢复、个人导出、HTTP 鉴权、前端交互和错误状态。界面提供 42px 起的主要操作区域、键盘标签切换、焦点样式、深色模式、窄屏布局及 `prefers-reduced-motion` 支持。

这些测试不替代真实浏览器视觉与触控验收。上线前还应检查桌面/手机的拖动与滚动、长文本、200% 缩放、慢网与断网恢复，以及部署的 HTTPS、认证配置、快照恢复、磁盘权限和容量。模块不是对整个平台生产安全性的认证。
