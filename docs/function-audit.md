# 功能审查与减负优化

本次从日常使用链路、重复程度、输入成本、外部依赖和已确认的代码问题出发。没有读取实际用户记录、采集使用次数或上传行为数据，因此下面的频率判断属于产品建议，不是个人使用统计。保留或删除最终应以你的真实使用习惯为准。

结论：当前更需要整理已有功能，而不是继续增加一级页面。采用可恢复的入口降级，未删除任何功能、API、历史记录或数据文件。

## 24 个页面的取舍

| 页面 | 判断 | 理由与处理方向 |
| --- | --- | --- |
| 今天 | 核心保留 | 把今日安排、待办、随手记与生活小组件集中在一起；购物、快递和重要日子不再扩张成独立页面。 |
| 智能日历 | 核心保留 | 统一查看安排与跨模块记录有明确价值；继续优先保证日期、可读性和来源清晰。 |
| 待办清单 | 核心保留 | 使用门槛低，适合承接多数日常任务，作为默认任务入口。 |
| 备忘录 | 核心保留 | 通用记录工具，应优先保护自动保存、查找与恢复体验。 |
| 心情日记 | 独立保留 | 隐私、日历与趋势用途不同于普通备忘录，不建议只为了减少页面而合并。 |
| 随身工具 | 核心保留 | 计算、计时和本机处理有直接用途；继续放在一个工具集合内。 |
| 今天吃什么 | 保留 | 符合高频决策场景；本地推荐应始终可用，AI 作为可选增强，不依赖授权成功。 |
| 运动日常 | 按习惯常用 | 对有锻炼习惯的人有持续价值，保留训练、饮食与日历联动，不再拆成更多页面。 |
| 生活保养站 | 按习惯常用 | 周期性事项与一次性待办的规则不同，保留其独立的完成后重算与历史。 |
| 生活账本 | 按习惯常用 | 高频但依赖持续记录，不应强迫每个人使用；保留快速记账和导出。 |
| 物品管家 | 按需保留 | 初次录入成本较高，到期、保修、借还才是核心价值；购物清单继续嵌入其中。 |
| 专注会话 | 按习惯常用 | 训练专注节奏与记录不同于普通倒计时，保留暂停、休息与任务联动。 |
| 文件快传 | 可选入口 | 场景明确但依赖同一局域网，不需要长期占据常用导航。 |
| 订阅管家 | 可选入口 | 周期性费用不同于流水记账，但通常按周/月查看，可作为账本周边工具保留。 |
| 随手收藏 | 可选入口 | 与浏览器书签部分重叠；待读、分类与应用内检索仍有价值。 |
| 生活足迹 | 低频回顾入口 | 本质上是已有记录的聚合，不应要求重复录入，也不宜当作每天必须处理的页面。 |
| 学习目标 | 可选成长入口 | 对长期学习有用，但不应成为日常应用的必填前置条件。 |
| 学习任务 | 有合并价值 | 与待办有重叠，但包含目标关联、估时和状态流转；本轮只收纳入口，不贸然迁移或删除。 |
| 智能规划 | 可选进阶入口 | 需要可用时段与容量配置；适合确有排程需求的人，不适合作为基础使用门槛。当前规则排程不是 LLM。 |
| 学习洞察 | 低频复盘入口 | 更适合每周查看而不是常驻高频页面；数据不足时不应制造结论，复盘草稿必须可靠。 |
| 单词学习 | 可选成长入口 | 学习链路明确，与日常工具并列存在，不强迫非学习用户安装词书。 |
| 英语精读 | 可选成长入口 | 与背词的用途不同，但依赖资讯源可达性；缓存与失败提示比增加来源数量更重要。 |
| 阅读书房 | 可选成长入口 | 阅读体验有独立价值；外部下载、版权提示与阅读记录应优先于扩充花哨统计。 |
| 探索生活 | 低频可选入口 | 人生地图、博物馆、声音与选择工具可保留为兴趣内容，不再继续增加独立导航页。 |

未来如要真正合并学习任务和待办，应先明确字段映射、任务状态、目标关联、日历/专注引用与导出兼容，再迁移并保留回滚方案。仅删除页面会留下断开的引用，本轮没有执行这种迁移。

## 已实现：可恢复的精简导航

- 侧栏点击「整理导航」选择常用入口；默认推荐 12 个。这个默认值不是对你习惯的推断，可随时修改。
- 精简模式中，其他页面从各组「其他 N 项」展开；当前激活页面不隐藏。关闭精简模式后恢复全部 24 个入口。
- Ctrl/⌘+K 仍检索全部页面，已有首页快捷入口和 URL 跳转不受折叠影响。
- 选择不是功能开关，不停用接口、不删除数据，也不会因为没放入常用而停止该模块必要的业务处理。
- 偏好按用户 ID 保存在当前浏览器 `daynest.navigation.<user-id>`。不上传、不跨设备同步、不写入服务器快照；清理浏览器数据后会恢复推荐。分组临时展开状态不持久化。
- 损坏的偏好降级为推荐布局；保存失败保留编辑选择；其他标签页冲突需要确认。账号切换清空本页选择，不覆盖另一个账号偏好。
- 手机菜单的焦点循环排除已经折叠的按钮。手机打开导航设置时先收起侧栏，关闭设置后焦点返回菜单按钮。

## 已实现：后台请求减负

- 初次登录、手动全量刷新仍核对所有核心模块，以保留现有依赖和失败隔离。
- 定时后台同步只请求概览、活动专注会话，以及当前页面需要的核心数据。例如首页只需概览、待办分类、待办、活动专注和当日安排，共 5 个核心请求。
- 自动测试中，无词书子请求的旧全量场景至少需要 15 个请求；有词书时还会增加词库、队列和概览请求。这个对比只计算核心控制器，不代表整站所有网络请求，也不是耗时或性能跑分。
- 重叠的后台刷新合并为一批；有手动全量刷新时不再叠加定时批次。切换页面时按需补读；若旧页面批次还在进行，完成后为当前页面补一批，不让新页面一直等下一个定时周期。
- 未请求模块保留缓存，不清空为零，不误报为已重新读取。未改变天气、提醒、文件传输等独立控制器的更新规则。
- 统计范围、周次和规划周的请求加了版本及参数检查，迟到结果不覆盖较新的选择。

## 已实现：数据交互修复

### 周复盘

- 写作时标记草稿，自动/手动刷新只更新汇总，不覆盖已编辑字段。
- 提供放弃修改；切换周次需要确认，保存中禁止切周与重复提交。
- 保存期间新输入保留，并明确提示还需再次保存；失败保留草稿。
- 确认写入成功后先保留服务器返回的复盘，再读取汇总；回读失败不把成功保存误报为写入失败，也不拿旧文本覆盖本次保存。
- 切到另一周后先清除旧周表单；新周加载失败时禁用保存并显示错误，不会把旧周文字错误保存到新周。未保存或保存中的复盘也纳入退出/刷新检查。

### 相关性

- `0.00` 不再被当成“至少需要 3 天记录”。
- 分别显示有效样本不足、数值变化不足、统计不可用、有效的零/正/负相关，并显示有效天数。
- 未记录的心情/压力不当成有效样本。至少 3 天只是计算门槛，不代表样本已经足以形成稳定结论；页面仍明确说明相关性不代表因果。
