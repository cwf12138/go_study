# 产品体验与可靠性整理

本轮重点是现有功能的共享体验和已确认的问题，不再增加独立功能页。覆盖现有 24 个入口的导航、基础可读性与交互设施；不宣称每个领域模块都已重构、穷尽缺陷或达到商业上线标准。

设计参考 [Todoist 快速添加](https://www.todoist.com/help/todoist/features/use-task-quick-add-in-todoist-va4Lhpzz)的低输入门槛，以及 W3C 对[状态反馈](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)和[点击目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)的说明。借鉴操作原则，不复制品牌素材；不是 WCAG 合规认证。

## 已实现

### 页面与手机菜单

- URL 使用 `#calendar`、`#memos` 等页面标识。点击导航写入历史；浏览器后退、前进及刷新恢复对应页面；重复点击当前页不新增历史。
- 未识别的标识回到今天；退役入口仍按原兼容规则跳转。URL 不保存日记、搜索词、取件码或表单内容。
- 当前导航标注 `aria-current`，浏览器标题随页面变化；提供键盘「跳转到主要内容」及页面切换播报。
- 同一页面会在当前打开期间记住最近滚动位置，不保存到磁盘，也不保证刷新后保留每个子视图或筛选条件。
- 手机菜单开启后显示遮罩，背景区域不可操作，Tab 在菜单内循环；Esc / 遮罩关闭并归还焦点。选择页面后焦点移到主要内容；跨断点恢复桌面布局。

### 可读性与反馈

- 常用表单标签、状态和主操作提高到 14px；手机输入提高至 16px。较强的模块选择器仍可保留自身样式；阅读器自定义字号不被统一重设。
- 表单原生约束错误显示在字段旁，关联 `aria-describedby` / `aria-invalid`，聚焦首个无效字段，展开包含该字段的折叠区域。修正或重置后移除错误，保留原有辅助说明。
- 主应用、日历、备忘录、英语精读及阅读书房接入共用提示。错误不自动消失；成功提示 6 秒后关闭，悬停或键盘聚焦时暂停。未解决错误不会被后台成功提示盖掉，关闭后再展示最近一条排队的成功提示。
- 模态弹窗中的提示挂在弹窗内，避免被原生对话框顶层遮住；提示关闭按钮可键盘操作。
- 各模块自有的行内状态与恢复栏保留。侧栏连接文字反映核心同步结果，不再无条件写“API 已连接”。

### 草稿与保存

- 目标、任务、待办、待办分类、手动时间块与首页随手记增加刷新/退出草稿检查，不持久化原文。
- 主应用以及备忘录、日历、阅读、收藏、账本、订阅、物品、购物、运动与饮食、保养、探索、展品、录音、文件快传注册自身的未保存/进行中状态；退出登录前统一确认。
- 目标、待办和分类表单在请求期间拒绝重复提交；保存期间继续输入时保留新内容，不无条件重置表单。保存成功后列表刷新失败与写入失败分别提示。
- 快递收件、重要日子在切换编辑记录或放弃表单前检查修改，刷新前检查待确认请求；关闭收件夹保留本页表单，但不保证刷新后恢复。日历关闭和 Esc 检查未保存修改，保存中禁止关闭。
- 这些保护不是离线保存、自动合并冲突或所有 POST 接口的幂等保证。创建请求超时后请先核对列表；不要通过连续新建来猜测保存结果。已有模块的原样重试协议保持不变。
- 另一个标签页更换账号时，以账号隔离为先清空本页旧账号界面；不能保证保留旧账号尚未保存的文字，请在切换前保存。

### 连接、导出与后端

- 核心请求与日历请求同时尊重调用方取消和超时；成功响应检查数据封装，204 正常作为无内容处理。
- 初始化连接失败、503 等临时故障保留令牌并显示重试；401 才清除失效登录状态。令牌保存不代表离线身份验证，服务仍需恢复连接。
- 跨标签页切换账号不会由旧页面删除新账号令牌或新账号的持久化计时信息；旧账号迟到响应被忽略。英语精读补充读取响应正文后的账号检查。
- 个人导出有 30 秒超时，同路径请求防重复，下载前再次检查账号；退出时取消正在进行的导出。跨账号响应不触发下载。
- 私有路由 404 / 405 返回 JSON，405 保留 `Allow`，错误返回请求编号以关联日志。与业务对象已删除的 `not_found` 区分，日历不再把“日程不存在”都解释为缺少接口。
- `/api/` 默认 `Cache-Control: no-store`，保留流接口等已有明确缓存头；不缓冲下载或 SSE。请求日志记录首个已提交状态，不被后续重复 `WriteHeader` 覆盖。
- 日历通知授权改为显式点击「允许浏览器提醒」，不在保存日程后顺带请求。关闭网页/休眠不保证通知送达。
- 每日专注目标未设置时默认 60 分钟，避免 `Number(null)` 将缺省值误判成已设置的 0。

## 验证与手工验收

自动检查：

```powershell
go test ./...
go vet ./...
node tools/product_shell_smoke.cjs
node tools/app_reliability_smoke.cjs
```

其余各模块 `tools/*smoke.cjs` 也需一起运行。本轮自动测试使用临时目录和内存模型，不打开或改写真实数据，不进行真实通知授权、录音或上传。

真实浏览器视觉/触屏尚未验收，建议重启服务并刷新后检查：

1. 从今天依次进入日历、备忘录、待办，使用前进/后退，并在各页刷新；确认导航、标题、内容一致。
2. 将窗口缩到 390px：检查菜单遮罩、Esc / Tab、输入字号、弹窗可滚动、按钮不重叠；再切回桌面宽度。
3. 创建表单留空触发错误；修正字段后错误消失。保存时继续输入新内容，确认不会被清空；保存失败保留原文。
4. 制造请求错误，等待超过 6 秒，确认错误仍可见；触发普通成功提示，不应遮盖旧错误。检查原生弹窗中的提示。
5. 留下备忘录、收件夹或日历草稿，尝试退出/刷新并取消离开；确认内容还在。手动丢弃后不应继续误报。
6. 测试浅色/深色及系统减少动态效果，确认焦点轮廓和错误文字可辨认。
7. 使用独立测试数据：保留登录令牌后暂停服务、刷新、恢复服务并点重试，验证临时故障不清登录；在另一标签页退出/切换账号，确认旧界面不再显示。

本轮不改变账户模型、数据快照格式、部署配置或外部服务地区限制；未修改真实 `data/studyflow.json`。
