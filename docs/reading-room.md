# 阅读书房：产品升级与发布检查

## 使用流程

1. 从世界名著目录搜索书名或作者，加入书架后打开正文。首次打开需要服务器访问外部书库。
2. 从“继续阅读”卡片返回最近阅读的未完成书籍。书架支持标题/作者搜索与阅读状态筛选，按最近阅读排序。
3. 阅读器支持章节、页码跳转、全文查找、沉浸阅读、三种配色、字号与行距。配色、字号和行距保存在本浏览器。
4. 全文搜索不区分大小写，至少两个字符，最多展示 60 个匹配页面；点击结果跳转。
5. 收藏当前页、记录本页笔记，或导出 Markdown 笔记与书签。笔记支持原位编辑，保留页码与创建时间；删除前二次确认。同一页面重复添加书签不会生成多条。翻页和关闭前会提醒未提交的笔记草稿。
6. 古诗文保留原文/译文对照、注释、收藏、诵读与研习笔记，提升正文与注释的可读性。

## 保存与网络

- 翻页后延迟保存位置；页面可见时每分钟同步一次，关闭阅读器时等待保存结果。失败会显示重试入口。
- 浏览器的阅读书房写请求串行执行；单个 Go Service 实例按用户使用有界分片锁保护书架、进度、书签、笔记及古诗文记录的读改写，避免不同字段相互覆盖。这不等同于多实例事务或多设备同一字段的版本冲突解决。
- 关闭后或切换到后台不继续累计计时，下载等待时间不计入阅读时间。阅读时长为估算值，不是精确的注意力测量。
- 网络失败时不会自动重放已经发送的时长增量，以免响应丢失造成重复计时；因此异常情况下时长可能少计，位置可以重试保存。
- 目录、书架、古诗文和统计分别加载；外部目录故障不会阻塞已经返回的个人书架。
- “加入书架”不等于离线下载。正文目前是服务器内存缓存，重启或缓存失效后需要重新访问来源。此版本不承诺断网阅读。
- 阅读设置仅存本浏览器；阅读进度、书签和已提交笔记使用现有后端持久化。没有新增快照结构，也没有迁移或清空用户数据。

## 发布前必须完成

- 在真实 Chrome/Edge/Safari 中验证桌面、平板、手机布局，以及键盘、屏幕阅读器、深色和减少动画偏好。当前工具环境没有可连接浏览器，尚未完成视觉验收。
- 配置 HTTPS、生产密钥、访问控制与请求限制；验证登录过期及不同账户隔离。
- 配置并演练业务快照的备份与恢复，确认数据目录持久化和磁盘告警。
- 用部署服务器验证书库网络可达性、超时、限流和正文下载失败；进行预期用户规模的并发测试。
- 核验每本书在服务地区的版权与来源许可。保留“原书与许可”入口；不要把公共目录中的所有作品视为全球任意商用。
- 多实例部署前，将当前进程内并发保护升级为数据库事务；继续完善进度更新幂等、多设备同一字段冲突处理及监控告警。

## 自动检查

```powershell
node --check internal/httpapi/assets/literature.js
node tools/literature_ui_smoke.cjs
go test ./...
```

自动测试覆盖页面控件引用、全文搜索与上限、连续翻页保存、保存失败反馈，以及既有 Go 服务回归。它们不能替代浏览器视觉验收或生产负载测试。

本轮新增服务端并发写入、重复加入书架/书签、笔记编辑与权限校验测试。新增编辑接口后，需要停止旧进程并重新运行 `go run ./cmd/api`，单独刷新网页不能加载新的 Go 路由。
